# CombatEvidence 对局调查时间线

独立本地浏览器工具。原始归档和已有分析数据库只读，索引写到新的分析目录；无需 Unity Editor，也无需先知道 EventId。

## 打开日志

1. 双击 `Tools/Open-Investigation.cmd`。
2. 选择完整证据导出目录，或同时包含 Host、Client 导出的上级目录。必要证据问题包也用同一入口打开。
3. 等待首次导入和索引完成，浏览器自动打开本机页面。服务仅监听 `127.0.0.1`；关闭启动终端即停止服务。
4. 选择对局、来源端、玩家/敌人、时间范围及类别，点击“查询完整归档”。“继续加载”可遍历全部匹配结果，不受当前页面条数限制。
5. 点击事件展开“输入 → 判断 → 实际变化”，或输入本端秒数查看状态。原始 JSON 是可选详情。
6. 点击“导出问题”，填写描述并计算上下文；确认预计体积与缺口后保存。包内 `report.html` 可直接阅读，原证据及其附件保持原始字节。

依赖 Python 3（仅标准库），启动器使用 PATH 中的 `python`。默认新分析目录位于 `%LOCALAPPDATA%/MonsterSupergroup/CombatInvestigation`。首次导入需要完整读取归档；之后使用启动终端输出的分析数据库路径可直接复开。

```powershell
# 同时导入两端；输出应在原日志目录之外
.\Tools\Open-Investigation.ps1 -Source 'D:\Evidence\Host-export','D:\Evidence\Client-export'

# 从既有 CLI 分析数据库创建独立索引，不更改该数据库
.\Tools\Open-Investigation.ps1 -SourceDatabase 'D:\Analysis\evidence.sqlite'

# 复开已经建立的新版分析数据库
.\Tools\Open-Investigation.ps1 -Database 'D:\Analysis\investigation.sqlite'

# 原 CLI 保留，并可进入同一个页面
python .\Tools\CombatEvidence.py serve --roots 'D:\Evidence' --output 'D:\NewAnalysis' --open
```

不要选游戏项目根目录作为归档。正在写入或仍有未检查点 WAL 的分析数据库不是不可变快照，工具会要求完成导入后再打开。既有新版索引不原地升级；版本变化后从原归档或原分析库创建新的分析目录。

## 页面解释规则

| 内容 | 解释边界 |
|---|---|
| 对局 | 按 run、round 和显式 capture 集合限定，不按文件夹名猜测角色。boot 归属原进程。 |
| 来源 | 显示实际角色、包 BuildId、记录角色/视角及来源端；未导入另一端不等于该端没有参与。 |
| 对象 | 本地出生实例和化身代次单独显示。对象筛选限定本端实例，展开可读取所选 capture 集合里的跨端关联。 |
| 时间 | 每个 capture 本轮第一条单调时间记录为零点。不同端零点不代表同步，不能直接相减得到单向延迟。 |
| 状态 | 每字段、每视角分别给出可靠恢复、最近观测或未知。记录时间、距离所选时刻的间隔、基准与原始指针可查。 |
| 范围外上下文 | 状态基准、父子事件、批次、权威结果与依赖可能位于筛选范围之外；保留原因和范围标记。 |
| 名称 | 内容目录必须与记录包 BuildId 和目录哈希匹配。旧包没有目录时保留类型和 ID，不用当前项目命名历史内容。 |
| 64 位数值 | 序号、EventId 等在网页接口中保留字符串精度。原始文件不转换。 |

有有效基准、连续变化、完整依赖和覆盖契约才标“可靠恢复”。只有观察记录时标“最近观测”；未采集、缺基准、出生歧义、缺附件或缺口无法排除变化时标“未知”。后来出现的恢复点不能消除早先历史缺口；未来记录不能反向补过去。

攻击区分计算请求、本地预测、服务端判断、权威输出与 Client 应用。一次输出合并多个命中时不拆成虚假的逐次实际伤害。未见 contact 不证明没有碰撞。拾取对象消失不证明玩家获得收益；重复回血回执不是第二次回血。装备卡的选择与装备目标确认是不同阶段。

## 四轨诊断

业务等待、Steam 待发送、本地帧、日志队列独立判断，允许同时存在。轨道区分已观察到、覆盖内未观察到、证据不足、数据无效、不适用。无样本不会当作零值。

- Steam 字段逐项验证，保留异常原值。旧约 `9.22e15 ms` 排队值不可用于判断。有效 pending 字节和无效排队时长可以并存。
- 历史待确认年龄没有统一时钟能力标记时不可用；待确认数量仍可作为独立事实。
- 新 Diagnostic 秒级观测携带时钟读取边界、SDK 读取结果和字段有效性，不增加 SDK 查询频率。
- 帧轨标出超过 100 ms 的样本；一秒统计窗口不是精确事件发生时刻。
- writer 非零队列表示有待处理记录，并不自动证明持续瓶颈；刷新墙钟耗时不等于磁盘等待。
- 单人 Host 且有效连接观测证明无远端时，Steam 为不适用。证据不足则保持未知。
- 图表按端、连接和指标分别显示离散样本，不连接成跨端统一时钟曲线，不从时间重叠断言因果。

## 未来归档采集

新调查采集仅在 Diagnostic 配置中默认启用，启动元数据记录实际能力。Standard 保持原有采集。比较开销时可在同包中关闭新增采集：

```text
--combat-evidence-profile=diagnostic --combat-evidence-investigation=off
```

新增状态以出生/恢复基准和变化记录保存构筑、等级经验与选卡事实；服务端提交和 Owner 实际应用保留不同视角。沿用既有构筑 revision，经验等独立同步字段没有共享 revision 时不伪造跨端一对一对应。当前完整 progression 恢复快照还包含选卡恢复字段，未声明全部变化连续，因此整体标为“最近观测”；XP、等级和提交结果仍完整保留，不宣称该混合快照已能可靠恢复任意中间时刻。

拾取记录生成、请求、竞争判定、预约、等待原因变化、实际收益和结束；选卡记录候选、请求、拒绝、返回、装备二阶段、构筑修改与实际应用。复用既有 drop/claim、event/option 和参与者身份，不增加网络协议字段。

玩家构筑变更监听只读观察实际状态，不改变战斗判定；构筑操作开始与完成分别记录，异常期间不能沿用旧状态宣称可靠。采集异常进入已有失败统计和完整性机制，序列化对象在入队前冻结，费用通过已有预算准入并随保存释放。

构建时生成与包身份绑定的内容名称目录，运行时只读取一次。无需逐帧记录构筑，不在每次攻击中复制完整祝福，不新增键鼠录制，也不扩展完整物理回放。

## 必要证据包

`investigation-package.json` 保存选择条件、问题、必要/额外记录清单、原覆盖事实、时钟起点、原路径和文件哈希。`investigation-report.json` 为可读报告的派生数据；`original/` 内为保持原字节的容器、附件和相关元数据。

依赖展开到闭包，不用固定秒数窗口或页面条数截断。由于复制完整原容器，可能带入相邻的额外记录，其数量和身份单独列出。原采集缺口与本次有意未导出范围分别保存。缺依赖仍可保全问题包，但完整性为失败/未知。

重新导入会核验文件哈希、路径、容器及附件依赖；缺失文件、冲突副本、越出包范围等不能被最终 Complete 标记掩盖。导出后分析不依赖原日志目录。报告中的原始指针保留可追溯信息；重新导入后的有效文件指针指向包内文件。

## 验证与交付门槛

Python 测试覆盖全量稳定分页、64 位 ID、局/端/出生边界、上下文、状态降级、四轨有效性、导出依赖和离线重导入。Unity 测试覆盖新采集门控、状态变化、拾取重复回执、构筑异常、内容目录及已有保存/完整性行为。浏览器实测验证筛选、展开、状态和导出操作。

真实历史验证使用弱机 589,398 条归档和旧双端归档。旧 Client 的 12,811 条丢失仍保留为历史不完整；弱机样本是单人 Host，不算 Client+Host 网络验收。

Editor 短混合负载用于报告增量字节、任务数、入队计费、生产耗时、队列峰值和排空时间。它不是实战帧耗时或持续吞吐测试；不工作的分配计数器必须报告不可用，不能写成零分配。

新 Player 正式交付仍须同包 Host/弱 Client 十分钟实战通过既定门槛：零拒绝、零捕获/不可恢复写入失败、依赖完整、计数闭合、普通队列峰值不超过 75%；可用内存连续十秒低于 1 GiB 或新增明显卡顿不通过。当前历史弱机峰值约 502 MiB，不能据此宣称新增采集容量验收已通过。本实现不替代 writer 吞吐优化，不处理碰撞阻挡定位。
