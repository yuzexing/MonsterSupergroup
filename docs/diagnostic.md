## 1. 目标与取舍

将日志系统改为“保留业务输入、关键判断和状态变化”，减少重复调用记录和重复状态副本。覆盖：

- 单个敌人的伤害异常，包括多人攻击、多层及多段 DOT。
- 玩家的伤害计算、攻击频率、漏命中和累计输出统计。
- 玩家与怪物的状态、位置、权限和死亡同步。
- 网络积压、发送失败、乱序、断线及恢复。

沿用已确认的要求：自动落盘、在线跨端复制、断线续传、每局 8 GiB、目录总计 32 GiB、总缓存 128 MiB、写入队列 32 MiB。正常移动保留可还原的紧凑输入，不采样关键战斗输入。

本次修复日志系统及取证能力，不修改伤害规则或同步权限；发现业务错误时输出独立、可复现的回归夹具。

## 2. 精简记录与修复过载

### 删除重复内容，保留回放语义

- 替换高频 `Advance` 的逐实体“进入／完成”两条通用日志，使用紧凑执行块保存调用顺序、实体、实际时间步和必要的执行上下文。回放逐次展开执行，不能把多个时间步相加，否则可能改变 DOT Tick 与浮点计算结果。
- 空返回值不再单独生成 `replay.output`。执行块明确区分正常完成、异常中止和记录缺失；有意义的返回值、拒绝原因及状态变化继续保留。
- 重复设值和正常移动采用字典引用、差量及批量编码；保留原始顺序和输入，不把“没有变化”误当成可以丢弃的业务调用。
- 伤害、提交、结算和 Replica 各阶段共享同一份输入引用，分别记录本阶段判断，避免反复复制整个批次。
- 构筑、装备参数、状态定义、击退曲线等不可变数据按内容哈希保存一次；变更时生成新版本。清理旧文件时保留当前回放区间引用的全部依赖。
- 每秒观察快照仅保留身份、位置、权限、关键状态、生命、死亡表现及待确认数量；完整去重缓存、DOT 进度等放入每十秒及关键边界的检查点。
- 重复异常保存首次调用栈、次数、起止时间与关联对象；移除正常流程和重复异常的逐次 Console 调用栈打印。生命周期和实际处理结果仍保留。

### 控制内存与后台工作

- 入队前预留内存预算，再复制必要数据；后台不得引用正在变化的业务对象。
- 修正空值也累计固定大额费用的粗略估算；队列、共享数据、检查点和复制缓冲统一计费，池化缓冲按实际容量计费。
- 使用有界不可变记录块，减少匿名对象、字符串、重复 JSON 编码及数组复制。每块达到 64 KiB 或等待 100 ms 即提交；每秒刷新持久化水位。
- 本地写盘与复制的扫描、读取、压缩分开调度。复制只读取已刷新数据，使用增量文件目录，避免反复扫描整局文件。
- 保留 4 MiB 关键记录额度，优先保障伤害、状态变化、检查点、异常和覆盖信息。过载时先舍弃观察快照；关键输入若仍无法保存，必须明确标记对应区间不可可靠回放。
- 缺口记录不依赖已满的普通队列。超过精确区间容量时，合并为保守的未知范围；磁盘恢复后写出故障边界，并从新的完整检查点建立可回放区间。

### 格式与接口

- 保留 `IDiagnosticSink.TryWrite`，增加类型明确的紧凑执行块和共享输入引用；引入可注入的存储接口，用于慢盘、写入失败和刷新失败测试。
- 日志与回放格式升至 2；离线工具兼容旧版文件并展开紧凑记录。
- 诊断复制协议升至 2，握手声明格式能力；游戏战斗协议保持当前版本。遇到不兼容的诊断端，继续本地采集并记录复制缺口。
- 现有 `IReplayAdapter` 增加伤害计算和输出统计适配器；继续使用实际业务实现，不能直接采用日志里的最终判定。

## 3. 四类问题必须保留的证据

| 问题 | 必须记录 | 工具应回答 |
|---|---|---|
| 敌人受击、多人及 DOT | 来源玩家、攻击及派生事件、目标出生代次、构筑版本；请求伤害、实际扣血、前后生命与状态版本；DOT 实例、应用版本、TickIndex、层次及立即结算标记 | 谁造成了伤害，是否重复、漏算、归属错误或被拒绝 |
| 玩家输出异常 | 攻击请求与计划／实际发射时刻、攻击窗口、碰撞候选及过滤理由；基础属性、各修饰器参数与生效条件、实际随机抽样、取整过程；统计增量及原始 EventId | 错在属性构建、计算、攻击频率、命中链路、结算还是统计 |
| 玩家／怪物同步异常 | 消息接收顺序、连接及权限 Epoch、状态版本；预测／Canonical／显示状态分别记录；权限交接、位置修正、死亡确认、表现结束和销毁 | 哪一端从哪一步开始不同，旧消息为何被接受或忽略 |
| 网络异常 | 连接状态、通道、实际发送结果、批次与业务事件关联；每秒 RTT、吞吐、排队时间、待发字节、失败与复制进度 | 消息未产生、未提交、发送失败、延迟到达，还是到达后被业务拒绝 |

具体补齐以下边界：

- 将伤害日志关联到具体命中和伤害事件，不能只关联一个可能命中多个目标的攻击根事件。
- 为现有修饰器记录可还原参数及其读取的目标状态，回放重新执行修饰器与计算规则；未知修饰器明确报告不支持。
- 将输出统计的输入关联到原始 EventId，分别展示计算伤害、预测扣血、Canonical 扣血和界面统计，不预先假定它们应采用同一种口径。
- 网络成功发送只保存紧凑元数据与成员引用，不重复保存整个业务载荷；发送失败必须能追到受影响的业务批次。没有唯一业务编号的消息明确标注关联能力有限。
- 漏命中可追查到攻击发射、窗口、接触与过滤阶段。完全没有碰撞回调时，报告证据止于物理边界，并用 PlayMode 场景验证；不声称能够重放整个 Unity 物理世界。

离线查询新增玩家输出时间线、DOT 实例履历及连接履历，统一输出“输入 → 判断 → 状态变化 → 首个分歧 → 原始证据 → 缺口”。

## 4. 测试用例与验收

先建立能够暴露当前问题的测试，再修改实现。

| 测试组 | 场景及断言 |
|---|---|
| 真实负载过载 | 使用本次日志缺口前的输入分布、频率和载荷建立压力夹具；复现持续积压，修复后不再丢失关键输入，记录体积及内存明显下降 |
| 时间推进等价 | 变化的时间步、多控制器交错、暂停恢复、同帧状态增删；压缩前后 Tick 顺序、编号和状态一致 |
| 多人伤害 | 两人同帧命中、重复事件、重复批次、多人致死、过量伤害、选卡及换装期间在途攻击；能解释各事件，死亡与奖励只结算一次 |
| 多段 DOT | 多来源同状态、叠层、刷新、移除后重加、立即结算、断线接管及检查点恢复；已执行 Tick 不重复，新 Tick 不遗漏，来源不混淆 |
| 输出计算与统计 | 暴击边界、增伤叠加、条件未满足、取整、攻击冷却、重复／漏记统计；注入错误后查询定位到具体计算步骤或统计事件 |
| 命中链路 | 攻击未发出、窗口关闭、目标已死、同次接触去重、碰撞未上报；区分不同失败阶段，不把缺少记录直接解释为未发生 |
| 状态与位置同步 | 旧 Owner、旧 Epoch、Canonical 乱序、合法同版本 Tick 更新、玩家状态变化、位置修正、死亡后正血量、销毁后回执；找出首次不同及原因 |
| 网络与复制 | 注入延迟、乱序、丢包、发送失败、断线、Host 不可达、ACK 丢失和重连；本地持续写盘，副本去重且缺口明确 |
| 存储故障 | 慢盘、磁盘故障、超过 128 个不连续缺口、异常风暴、强制退出、容量清理；内存有界、业务不无限等待、恢复后的文件可读 |
| 诊断不改变业务 | 同一输入分别关闭日志、仅本地记录、开启复制；业务结果一致，回放重新计算得到相同状态 |

对稳定场景各运行三次，覆盖 50、200、500 只怪物、144 FPS 目标及高输出清场。每次至少持续三分钟，比较关闭日志、仅本地、全端复制三种模式。

验收要求：

- 正常测试负载下关键输入零丢失；故障注入下允许明确降级，禁止误报完整可回放。
- 总缓存不超过 128 MiB，写入队列不超过 32 MiB；统计持有内存、分配量与 GC，不能仅看队列计数。
- 主线程 P95 增量目标不超过 1 ms、P99 不超过 3 ms；编码、写盘、检查点和复制分别报告，并同时报告总开销。
- 文件体积作为辅助指标记录，同时验证输入展开与回放等价；压缩率不再作为高负载性能通过的替代条件。
- 跨端复制沿用每进程 2 MiB/s、每连接 256 KiB 在途预算；链路不足时显示复制滞后，负载结束且链路恢复后能够补齐仍保留的数据。
- 自动化注入验证查询与完整性机制；另须取得一个真实业务缺陷，从原始输入提取夹具，并以独立业务断言连续三次稳定失败。
