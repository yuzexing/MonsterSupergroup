# Enemy Debug 展开卡顿修复（2026-09-22）

已在本机 DX12 独立 Development Player 稳定复现，并完成代码修复与自动验证。修复针对开发面板展开后的卡顿；真实 Steam 双人复测仍由玩家完成，不能据此宣布此前的原生 GPU 崩溃已解决。

## 原因与修改

`NetworkEnemyDebugPanel.OnGUI` 原先在滚动区域中遍历全部行，对每只怪物调用一次带自动换行的 `GUILayout.Label`。滚动裁剪只限制可见内容，不会让未显示的条目跳过自动布局和文本处理。数百条包含血量、状态、目标、模拟权、交接信息的长文本，在每帧多次 GUI 事件中反复处理，造成 CPU 停顿和大量托管分配。

现在每页最多绘制 **4 条**，通过 `Previous / Next` 翻页，页内仍可滚动。所有怪物的只读快照、5 Hz 刷新、完整信息、两秒死亡缓存都保留。收起再展开保留页码；怪物减少、死亡缓存到期时页码自动回到有效范围；断线或换局清空页码。F3 与选卡隐藏规则沿用原逻辑。

增加 `EnemyDebug.OnGUI`、`EnemyDebug.Refresh` 两个 Profiler 标记，便于以后在完整 Profiler 捕获中检查这两条路径。本次没有调整敌人行为或网络发送频率来取得面板性能改善。

## 可重复实验

证据目录：`Logs/EnemyDebugPerformance/20260922-132048/`。

同一机器、DX12、关闭垂直同步与帧率限制，使用真实 Boot 加载 Gameplay 和正式 Enemy Debug 组件。保留两只普通怪，额外生成 400 个无 AI/美术的网络敌人对象，固定 **402 条**调试数据，隔离面板随行数增长的成本。每个版本按“收起 → 展开 → 收起 → 展开”各采样 10 秒，阶段间预热两秒。不启用 Deep Profiling。

| 条件 | 平均帧耗时，两轮 | 每帧托管分配，两轮 |
|---|---|---|
| 修改前，收起 | 2.86 / 2.80 ms | 72 / 71 KB |
| 修改前，展开 | **761.66 / 763.10 ms** | **40.25 / 40.23 MB** |
| 修改后，收起 | 3.08 / 2.86 ms | 75 / 72 KB |
| 修改后，展开 | **3.21 / 3.17 ms** | **117 / 117 KB** |

修改后展开窗口的 P95 分别为 3.74 / 3.63 ms，最大帧约 18 ms；原版本最大帧约 776 ms。所有指标来自 `before/result.json` 和 `after/result.json`，分配为整帧总量，不冒充面板自身的精确分配。该实验用于确认 GUI 热点，不代表真实 Steam 完整战斗的 FPS。

原探针中的 `refreshMeanMs=0` 不作为结论依据：在 Update 中逐帧清空采样可能丢失同帧尚未提交的刷新标记。保留原始记录，后续探针改为窗口结束后读取 GUI 样本，移除无效的刷新汇总字段。结论采用未受此问题影响的帧时间、整帧分配和同场景开关对照。GUI 回调标记本身也不包含回调返回后的延迟自动布局，不能用它冒充全部 GUI 开销。
