# Limbo 人工试玩说明 · Phase 6

人工压力以单人 Host 为主。本机双端入口用于联机技术检查，不提供局域网地址或 Steam 接入。

完整解压后双击：

| 入口 | 用途 |
|---|---|
| `1-Solo.cmd` | 单人 Host，自动准备后进入完整 Limbo |
| `2-Host.cmd` | 双人主机，等待两个参与者准备 |
| `3-Join-Local-Host.cmd` | 加入同一包启动的本机主机，地址固定 127.0.0.1 |
| `4-Archive-Latest-Logs.cmd` | 将最近一局的两端日志与版本清单打包到 Archives |

不需要 Unity Editor、工程目录或 F 盘。请放在可写目录并保留 EXE、Data 和所有依赖。启动脚本无法写日志时会报错，不会悄悄改用另一个目录。同一时间只运行一组主机；旧日志目录不会覆盖。

游戏底部显示版本、运行编号及轮次。移动、攻击、选卡和退出使用正常游戏输入。正常攻击会按装备规则执行；自由选卡，不要求指定构筑。结算后可通过界面重开，新 RunId／Round 会写入同一进程日志。不想重开时使用现有退出入口，再归档日志。

三个入口固定 Full、轻量记录，关闭自动移动、自动选卡、补血、无敌、定位、跳时和强制生成；F5 调试升级也禁用。没有定时截图，不需要为记录压力而停下操作。允许失败。

## 固定初始条件

31 个敌军片段；720.9 秒请求转场，等待已连接、存活玩家结束选卡等忙碌状态后结算，不要求清怪。Minos 战未实现。

玩家 500 HP、4.55 基础移速、初始武器 ID 1、XP 修正 2；出生 XP 分母 841.5766649882。保留种子 14301、当前 Nordic 地图、镜头和已恢复美术。击杀、移动、帧率和概率分支仍影响实际生成量，种子不保证每局出生完全相同。

默认 D3D11、1280×720 窗口、目标 60 FPS。实际分辨率、帧率设置、设置变更、初始化属性和每次接受的升级均进入日志。可以正常使用设置菜单，测试报告会区分暂停时间。

## 反馈方式

首轮正常游玩、自由选卡，重点留意开场、180 秒 Rusher、285 秒短片段和 599 秒后的叠加。不必边战斗边记笔记。

```text
版本／运行编号：
结束时间／原因（完成、死亡、退出、异常）：
压力明显变化的时间点：
主要感受（过松、过密、难以躲避、看不清等）：
异常及大致发生时间：
日志包：
录像（可选）：
```

如需归档指定旧局，在包目录执行 `Archive-Logs.ps1 -Session <运行编号>`。每个角色的日志独立，RunId／Round 区分重开。缺少正常关闭标记、仍在运行或存在坏行的记录会标为不完整。异常退出可能丢失最后约一秒缓冲，不完整文件不能证明通关。

## 日志口径

`launch.json` 固定版本与辅助开关；`*-audit.jsonl` 记录出生、玩家有效生命变化、实际构筑、选卡、暂停、1 秒统计、帧时间与写入耗时；`spawns-<RunId>-*.csv` 保存服务端生成尝试、成功、计数和无经验终止；其他观察器保留敌人首伤至确认死亡及陷阱状态。

伤害尝试与有效扣血分别处理；无法可靠关联的扣血来源标为 unknown。击杀用时从首次有效受伤开始，恢复生命后重新计时；自爆、淘汰、普通击杀不混算。存活峰值若来自每秒统计，明确为采样峰值。C 预算、L 存活目标、B 批次数量不能相加当成实际总生成量。
