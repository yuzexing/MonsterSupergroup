## 人工压力测试

优先单人 Host；双端用于联网正确性，不要求一人同时操作两位角色来判断多人难度。

从项目目录执行下面的入口，不传 `-AutoWalk`，由人工移动、攻击和选卡。使用新的 RunName，避免覆盖旧记录。已有 AI 试玩进程启用了 AutoWalk，不把该进程的界面重开当作纯人工移动局。

```powershell
./Tools/Run-LimboReference.ps1 -Role host -Profile stage2 -Port 8160 -Windowed -RunName manual-stage2-001
```

保留 500 HP、4.55 移速、武器 ID 1、XP 修正 2、当前镜头及 Nordic 地图。预览到 209.05 秒，不启动 Dash；不改来源数值，不使用补血、跳时、强制生成。基础难度反馈与后续 XP／镜头校准分开。

反馈以下内容即可，出生、受伤和波次细节由日志分析：

- 本局 RunName，是否到 209.05 秒，死亡／明显卡顿的大致时间。
- 哪段过轻／过重：开场、60 秒 Imp、105 秒精英、135 秒 Skeleton、180 秒 Rusher。
- 主要升级选择，是否有较长选卡／菜单停留，以及操作或画面异常。
- 结算后点“重新开始”，确认等级、生命、敌人及旧攻击／预警是否正常清理。

日志自动保存在 `Logs/LimboReference/<RunName>/host`。不需要人工抄录每次出生数。

## 可人工补验的空间项目

`spatial-b`（12 秒）、`spatial-barrier`（85 秒）、`spatial-overlap`（85 秒）为时间平移的隔离配置，不是正常主线压力局。可替换上方 Profile，并使用不同 RunName。

- B：预警是否看得清、敌人是否在提示位置生成、结束是否有残留。
- 围栏：能否阻挡移动、边界与画面是否对得上、收缩是否连续、入场后镜头／速度是否恢复、结束是否仍被无形墙挡住。
- 双端：两端看到同一事件，Client 不多刷一批，结束和重开后旧预警／碰撞均消失。

数值等待、同步时钟、占用释放、边界和重复回调由 AI 对照日志与代码核验；肉眼观察不替代这些检查。
