## 实现与配置

`NetworkExperienceWorld` 仍是唯一服务端入口，沿用 `ConfirmedKill`、现有经验计算、Collector 和 OwnerFinal 生命链。物品定义见 `GameplayPickupDefinition`；生产配置是 `GameplayPickupRules.asset`，并由现有 `NetworkCombatWorld.prefab` 引用，Boot→Gameplay 与 Limbo 共用。没有启动旧 `LootManager`。

经验在领取成功时结算，飞行只显示；血瓶依次经过地面、保留/飞行、等待回执、消费或返回地面。服务端按战斗时钟推进 0.3 秒退后与 0.5 秒飞入；忙碌暂停该玩家的血瓶。到达后 Owner 通过 `CombatantBinding.RestoreHealth` 回血，带领取凭据的生命报告与消费在服务端同一次处理内确认。

物品身份、展示、数值、场上上限、闲置容量和曲线放在定义资产中。首轮只实现 XP 与回血效果。后续新物品需要新增效果处理及必要回执，复用登记、资格校验、池和轮次清理；不会自动获得金币账户、背包或持久化能力。

修复过程中发现并处理：

- 直接开局无准备房轮次时，回执改用服务端 World 同步轮次。
- 重连时场上血瓶先于 World 客户端初始化到达，生成注册提前到网络客户端启动，防止缺失 Prefab。
- 回执过时只重发当前生命报告，不再次回血；提交确认前的后续受伤报告保留凭据。提交与消费一次完成。
- 已回血后遭受致死伤害，即使首份回执过时，重发的有效 HP=0 也不得因 `Alive=false` 被拒绝。未飞到玩家前已倒地则退回血瓶，两个顺序分别处理。
- 首版协议测试误把 53 字节未压缩预算当作 Mirror 实际编码长度；小值样本实际 15 字节，往返字段及预算分开检查。
- 旧 XP 测试硬编码 4 与出生 XP 不符，改查出生 XP × 玩家修正；未修改经验数值。

后台进程退出时仍有既有 ComputeBuffer 释放警告；候选包无画面启动还记录到镜头绑定前 FMOD Listener 与场景加载期间 EventSystem 警告。本轮没有证据将它们归因于拾取池，未将零测试错误描述为日志完全无警告。短时检查证明池复用和容量溢出不删除地面奖励；不代表大规模 GC、显存或长局性能验收。
