# Steam 轻量网络定位包

这是用于再次捕获拥堵的诊断包。保持现有发送、断开和战斗行为；未增加重试，也没有宣称历史拥堵已经解决。完整 CombatEvidence、replay、checkpoint、Deep Profiling 和故障注入均关闭。

## 双机测试

两端使用同一个游戏包，登录各自的 Steam 账号。建议把包内 `product` 和 `operator-kit` 直接放在 `C:\SteamNet` 下，不要重复嵌套完整包名目录；长路径可能使状态文件写入失败并留下空日志。入口会在启动前检查状态文件的完整路径。

- Host 双击 `operator-kit/Host-Network.cmd`。
- 弱 Client 双击 `operator-kit/Client-Network.cmd`。
- 各端进入菜单后，双击 `operator-kit/Verify-Running.cmd`。必须显示包身份与实际轻量配置校验通过。
- 使用普通 Steam 房间联机。手动战斗约八分钟，重点观察战斗开始后 280–330 秒、高怪量及一人倒下后另一人继续战斗。尽量覆盖原约 150–250 只存活敌人的负载；不要为了达到数字修改规则。存活怪量由日志记录。
- 出现发送拒绝或异常，仍能操作时继续约三十秒，再正常退出。未出现异常也正常结束这一轮。
- 等启动窗口完成收集，在各端双击 `operator-kit/Export-Case.cmd`，交回它打印的整个导出目录。不要只发 Player.log 或其中一个 JSONL。

不需要输入随目录变化的参数，也不需要粘贴多行命令。启动窗口持续等待游戏退出属于正常行为，请保持打开；校验和导出使用另一个双击入口。启动器按进程启动时间提醒八分钟，不会强制结束；实战时间以战斗开始计。补充实际现象、发生阶段及退出保存耗时即可。本轮双人覆盖不能替代原三人负载覆盖。

原 `Host-Local.ps1` / `Client-Local.ps1` 仍保留完整取证行为，本次请使用上面的 Network 入口。若 PowerShell 因本机执行策略拒绝脚本，可在当前终端运行 `Set-ExecutionPolicy -Scope Process Bypass` 后重试。

## 调查与导出

分析机需 Python 3.10 或更高版本，无第三方依赖。在 `analysis-tools` 中运行：

```powershell
python ./CombatInvestigation.py --roots '<Host 导出目录>' '<Client 导出目录>' --open
```

页面仅监听 `127.0.0.1`。选择对局，在类别中选择“Steam 发送拒绝”；可按连接实例、方向、频道和返回码筛选。展开记录查看发送尝试、失败批次内的真实业务对象、未知原因及后续事实。消息哈希相同不代表同一次投递；发送被接受也不代表对端已经应用。

默认异常范围按所选 capture 和连接实例计算，为首次拒绝前十秒至最后拒绝后二十秒；不跨端相减 UTC。预览并导出问题包：保留完整原 JSONL、status 及校验信息，额外带入的范围有标记；无需原目录即可重新导入：

```powershell
python ./CombatInvestigation.py --roots '<问题包目录>' --open
```

旧分析数据库的索引版本可能不匹配，请从原归档建立新的派生数据库。原日志与原数据库不修改。

## 结论边界

- `LimitExceeded` 独立证明 Steam 未接受该次发送，即使排队时长无效也保留此结论。
- writer 积压不证明 Steam 拥堵；无拒绝不能在采集有缺口时解释为没有故障。
- 展示最后拒绝、后续接受、有效队列样本和业务处理事实，不自动宣布恢复。断线、重连、缺样本不能作为恢复证明。
- Steam 的本地句柄、Mirror 编号与连接实例分别保存。跨端 SDK 消息号须在已确认的连接对应关系中使用；未能确认时保留候选或未知。
- EntityState 记录能指向真实网络对象，但不会解码所有 SyncVar；交接阶段由运行时观察补充，不能据时间接近强制匹配。
- 采集失败、批次解析失败、写入失败分别显示。缺正常结束或最终 writer 状态失败，整段采集标为不完整。解析失败时发送拒绝头仍可成立，对象关系显示未知。
- 首轮未复现则交付覆盖报告并停止；实际复现后只修复证据支持的一处原因，再用可比场景复测。注入通过或包构建通过均不能证明真实拥堵已修复。

## 实现边界

复用 `NetworkDiagnosticsObservation → LimboObservationLog`，保留现有四 MiB 后台队列和关闭机制。每秒记录有效性、流量类别、接收处理、帧统计及 writer 积压。紧凑网络索引连续落盘；不新增常驻分析服务或物理回放。真实测试仍需关注日志增长和采集缺口。
