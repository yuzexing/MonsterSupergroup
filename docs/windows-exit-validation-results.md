# Unity 6000.3.21f1 Windows 退出复测结果

验证日期：2026-09-13。本机此前可复现的 Windows UI Automation 退出崩溃已通过升级前后对照验证修复。没有修改网络退出流程、屏蔽异常退出码或关闭无障碍功能。

## 退出对照

新包均使用 Mono、正式 Boot → MainMenu → Gameplay 流程，无测试程序集、无验收宏。每次启动独立进程，通过游戏首页退出按钮结束；匹配 PID 检查 Windows Application Error 事件。

| 引擎 / 包 / 操作 | 次数 | 原始退出码 | 对应崩溃事件 |
| --- | ---: | --- | ---: |
| 6000.3.17f1 开发验收包，UIA 后退出 | 1 | 0xC0000005 | 1 |
| 6000.3.17f1 非开发验收包，UIA 后退出 | 1 | 0xC0000005 | 1 |
| 6000.3.21f1 开发包，UIA 后退出，D3D11 | 5 | 全部 0 | 0 |
| 6000.3.21f1 发布包，UIA 后退出，D3D11 | 5 | 全部 0 | 0 |
| 6000.3.21f1 开发包，用户亲自操作，D3D11 | 5 | 全部 0 | 0 |
| 6000.3.21f1 发布包，用户亲自操作，D3D11 | 5 | 全部 0 | 0 |
| 新版开发包 / 发布包，默认 D3D12，UIA 后退出 | 各 1 | 全部 0 | 0 |
| 新版开发包，三条设置路径后首页退出 | 3 | 全部 0 | 0 |

新版共 **25 次真实首页退出通过**。UIA 组确实调用窗口元素读取，包含运行期间和临近退出的读取；普通人工组由用户在记录窗口按 Enter 后亲自点击，助手只读取进程和日志，不读取游戏窗口。

自动组从退出点击前的信号计时：开发包 D3D11 为 0.31–5.03 秒、发布包为 0.83–0.85 秒；默认 D3D12 分别约 0.40、0.89 秒；设置路径为 0.33–0.36 秒。人工组的 6.43–17.15 秒包含用户切换窗口和移动鼠标，只是退出耗时上界，不能当作引擎清理耗时。

原版证据仍在 `Logs/NativeExitUpgrade/baseline-*-uia-visible`，其中 `windows-event-followup.json` 修正了早期记录器的事件漏匹配；原始转储只保留本机。新结果索引为 `Logs/NativeExitUpgrade/6000.3.21f1-validation/exit-matrix.json`，每组包含包哈希、启动 ID、原始日志、退出时刻及事件。

## 设置与运行回归

- 真实鼠标修改分辨率、Hz、FPS 后返回丢弃，再打开核对原值，正常退出。
- 真实鼠标应用三项设置、点击保留，实际 Esc 返回首页后正常退出。
- 等待 15 秒确认超时，分辨率和 Hz 恢复，再用 Esc 返回首页退出。FPS 按既有非显示模式设置规则保留已应用值，没有改变该行为。
- 设置专项四个进程（exercise、restart、dedicated、restore）全部通过且退出码为 0；检查中英、音频、30 FPS 实测、独占/无边框/窗口、显示确认与超时恢复、重启保存。实测 30 FPS 上限约 29.96 FPS。
- KCP Host＋两个客户端：本机 UI 组队、选卡/ESC 输入、客户端离开、Host 结束与意外停止、再次建房、全员倒地与连续重开通过。`combat-menu`、`run-end` 各独立执行 3 次；每次 combat-menu 同时覆盖退出后再开单人局并退出。另有两次 `combat-menu-solo`。
- 三进程回归实际检查服务端接受的怪物位移、自动攻击、重开后的新 Avatar 与移动，不只检查房间字段。它们通过验证探针驱动现有 UI/服务接口并退出，**不计入上述 25 次真实首页点击**。
- 测试端口 7796、7797 均释放；原用户设置按备份逐字节恢复。
- Editor 工具测试 8/8，本地化、选项、菜单、卡片及好友页 PlayMode 测试 24/24；记录器自检 8/8，工具目录与文档校验通过。
- 升级迁回主项目后，再次导入、编译和正式资源校验通过，Editor 正常退出。最终报告：`Logs/ProjectTools/20260913-233112-019-validate.all/result.json`。主项目依赖解析耗时约 331 秒，未出现新的依赖版本差异。

## 单独保留的失败记录

扩展 EditMode 为 **660/664 通过**，四项旧迁移测试在 6000.3.17f1 同样失败（旧版对照 43/47 通过）：

- 三项仍断言 Prefab 的初始武器为 2，现有已提交资产实际为 6。
- 一项大招测试读取已经删除的 `title` 字段，产生空引用。

失败名称和断言在新旧 XML 中一致；没有为了通过测试修改玩法资产或删除断言。旧版对照位于主项目 `Logs/NativeExitUpgrade/old-migration-comparison`，新版完整 XML 位于新结果目录的 `editmode-regression`。

设置专项首次失败是旧测试在 `SetLanguage("en")` 后只等一帧就检查文本，早于异步表格/字体加载完成。已改为等待已应用语言，并保留超时和译文断言；正式本地化代码未改。修正后专项通过。

用户按物理 Esc 中止的首轮、未记录退出请求就结束的首次默认图形轮，以及早期隐藏启动/安装中断等记录全部保留并排除，既不计成功，也不冒充新引擎崩溃。默认图形轮重新通过。早期新包报告中 `testAssemblies: [null]` 是空列表序列化问题；实际 DLL 扫描为空，已修正后续记录输出，原始报告未覆盖。

## 升级差异与边界

6000.3.21f1 的官方修复 UUM-146676、旧版符号地址和本机实际触发条件相互吻合，详见[诊断记录](plans/windows-uia-exit-fix.md)。本轮结论只针对该退出故障；原 D3D12 PSO 缓存问题仍独立记录，不宣称所有退出原因或所有机器均已覆盖。

包依赖只接受新内置渲染包要求的 Burst 1.8.30、Collections 2.6.8 解析结果，manifest 和第三方插件版本不变。首次导入按现有 Localization 规则重新归组 Addressables；地址、内容 GUID、翻译、玩法数值保持。DOTween 自动补充其宏，Unity 保存三个新增 iOS 热状态设置字段；这些差异来自现有插件/引擎序列化，并非网络退出修复代码。

交付入口为 `Builds/PlayerDevelopment/MonsterSupergroup.exe`、`Builds/PlayerRelease/MonsterSupergroup.exe`；旧验收包与 6000.3.17f1 编辑器继续保留。复跑方法见[退出验证工具](player-exit-validation.md)。
